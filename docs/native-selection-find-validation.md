# MRK-49 native selected-source find candidate

This local research candidate starts from MRK-48 checkpoint `8f99d8a` on `spike/native-selection-find`, in a separate worktree. It excludes held MRK-46 preview work. This candidate now passes **177 shared tests and all 19 AppKit groups**, with successful unsigned Mac app and generic-simulator iOS build-for-testing. These results qualify bounded shared/native selection navigation and compilation, not attached UIKit interaction, actual OS input, accessibility or release readiness.

The whole-document native source editor has a **Find selected text** submenu containing the fixed **Next exact occurrence** and **Previous exact occurrence** titles. The current nonempty valid UTF-16 source selection supplies the entire query; selected contents never appear in menu titles. This is in-memory current-source navigation, separate from MRK-40's saved-collection search. There is no prompt, history, index, regex, replacement, case folding, overlapping-occurrence count, clipboard read, file/provider/URL access, network or script execution.

Matching uses `NSString.range` with `.literal` and, for previous navigation, `.backwards`. It is case-sensitive and preserves canonical Unicode distinctions: NFD and NFC differ. Next searches `[selectedEnd, sourceEnd)` then wraps through `[0, selectionStart)`; previous reverses `[0, selectionStart)` then `[selectedEnd, sourceEnd)`. Destinations cannot overlap the original selection. Adjacent matches are allowed. Each raw candidate must pass `SourceSelection.isValid`, including surrogate-pair and CRLF boundaries. An invalid CRLF-interior raw match is skipped with guaranteed UTF-16 progress; later valid matches remain reachable.

The whole report permits at most 1 MiB source UTF-8, 64 KiB query UTF-8 and 256 raw candidate checks **per direction across both wrap segments**. The 256th checked candidate can succeed. A 257th candidate refuses the report. If either direction exceeds its budget, both plans are absent: no partial navigation plan is exposed. Empty/invalid selection, source/query/candidate limits and no-other-occurrence have explicit disabled status items; the fixed command titles remain present and disabled when unavailable.

`SourceNavigationPlan` generalizes the existing heading plan with a validating factory and a compatibility alias. Heading-outline membership, validity, API and native scope guards remain in place. A plan captures exact source bytes and the original selection; retained menu actions refuse changed bytes or ranges. AppKit items retain themselves as targets and weakly reference the source view. Both platforms share their existing selection-and-scroll reporter path; no text replacement, native text undo grouping, autofocus, `becomeFirstResponder` call or editing-generation reset is added to navigation. Attachment, native focus, editability, single selection and marked-text guards are checked again at action time. Read-only source-copy/recovery views refuse navigation. UIKit has an independent whole-document `allowsSelectionFind` flag alongside the semantically unchanged heading flag; `NativeSourceEditor` sets both from `wholeDocument`. Its exact contextual-range and single-selection menu guards remain.

The MRK-47 source-revision/composition save guard is untouched. Selection-only reports must update exact model selection without scheduling autosave or rewriting the current conflicted recovery checkpoint. MRK-48 source formatting and insertion behavior are unchanged.
