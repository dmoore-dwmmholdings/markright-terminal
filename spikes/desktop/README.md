# MRK-9 desktop editor interaction spike

Local CodeMirror 6/Lezer Markdown candidate. This is not a Tauri application, full Markdown renderer or selected production framework. No document scripts execute; source is shown as text, never injected as HTML. It does not implement Markright file resolution/includes or use the native parser yet.

## Whole-document source mode

The explicit **Source mode** toggle reveals all syntax by reconfiguring only the preview decoration compartment. It keeps the same editor state, source-separator metadata, directional selection and history; keyboard activation returns focus to the editor. It is a whole-document editing view, not a read-only reading mode or a parser/performance fallback. Markdown parsing still runs, and the renderer remains partial.

The control exposes `aria-pressed` and a mode description. It refuses transitions throughout CodeMirror's `compositionStarted` phase and disables during composition; projection updates also wait for that broader phase. Review caught the initial use of `composing`, which is false before the first composition edit. A synthetic start-without-input/selection-update/bypass-disabled-click regression failed in both engines before correction. These programmatic/CDP observations do not establish real OS IME, assistive technology or VoiceOver acceptance.

Current evidence: **29 browser checks pass, 1 existing explicit WebKit CDP-composition skip** in `spikes/macos-editor/build/desktop-source-mode-browser-final-20261109.log`. Added flows cover exact BOM/mixed-ending source, reverse selection, inert markup, keyboard toggle/focus and undo/redo across modes. The before-fix log and error contexts remain in `desktop-source-mode-composition-before-20261109.log` and this spike's `build/test-results`; final output uses `build/source-mode-final-results`. Eleven system-WebKit groups also pass, including bundled control clicks with exact source/selection retained; that probe is not OS keyboard input. The separate unsigned Mac Verification product builds with warnings as errors. No existing preview tab or visible Debug app was reloaded; the preview offers this control on its next reload, which resets its temporary edits.

Tests cover inactive formatting/source fidelity, literal punctuation, whole code/table source units, inert HTML/script-shaped text, cross-block replacement with exact undo, a 1 MB edit smoke and Chromium composition text commit.

The initial preview decorates headings/emphasis/strikethrough and hides selected syntax markers outside the active line/block without rewriting source. Links/images/tables and all Markright extensions do not have complete renderers. Active preview follows the primary selection; multiple-cursor behavior remains a gate. Background parse-tree changes trigger decoration refresh. Composition maps existing decorations instead of rebuilding them until commit, but real OS keyboard IME/accessibility testing remains required.

These browser durations are test-runtime smoke measurements, NOT p95 input-to-paint evidence. Headless engines on macOS do not prove Windows/Linux shell behavior, actual WKWebView/WebView2 integration, filesystem access, packaging, screen-reader use, native startup or framework acceptance. The editor and native Swift prototype use different temporary parse/grouping approaches; a shared semantic/source-map contract still needs integration.

Independent source review identified exact-end caret ownership as a gap. The added fence/table-at-EOF regression initially failed in both engines; two-sided syntax resolution now reveals the full block while leaving a following empty line separate. All fifteen browser checks pass, with the one explicit WebKit composition skip retained.

A later empty-EOF regression also failed in both engines for unclosed fences. The candidate now keeps that editable line inside the fence while preserving the separate empty line after a closed fence. Nested quote/list cases pin the parser's container ownership. Latest desktop result: **17 passed, 1 skipped**; the skip is the existing WebKit CDP composition probe.

The initial harness normalized CRLF/CR to LF. The later `source-buffer.mjs` research adapter preserves each original separator beside CodeMirror's normalized editor text and maps original UTF-16 source offsets explicitly. It rejects offsets inside CRLF or surrogate pairs. New keyboard line breaks use the first original separator (LF if none); explicit text paste preserves the separators delivered to its handler. Edits joining CR and LF coalesce their editor boundary, and custom history effects restore exact deleted/changed separators through grouped undo/redo. Reloading a fixture resets history.

Latest evidence: **23 browser checks pass, 1 explicit WebKit composition skip**. Nine source-buffer test groups include 200 deterministic raw-source splice/undo/redo cases and a 150,000-newline stress case. Independent additional randomized history/offset probes found no blocking defect. These are scoped source-buffer findings: OS clipboard normalization, copy/drop/multiple-selection behavior, true OS IME, disk persistence and p95 paint remain gates. Metadata updates are O(line count), not an accepted production performance design. No imported files are saved by this harness.

The currently visible preview is kept alive by a removable user-session job, `com.dwmm.markright.local-preview`, serving only the synthetic fixture on 127.0.0.1:18790. It installs no login-start item or production service. Stop that owned job with `launchctl remove com.dwmm.markright.local-preview`; its logs are `/tmp/markright-preview-launch.log` and `.err`. Edits remain in browser memory and reset on reload.
