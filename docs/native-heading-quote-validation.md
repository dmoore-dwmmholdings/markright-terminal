## Literal source behavior

Heading commands prepend exactly `# `, `## ` or `### ` to each nonblank selected physical row. Blank and whitespace-only heading rows retain their original bodies and endings without a prefix. Blockquote prepends exactly `> ` to every explicitly selected physical row, including interior and selected leading/trailing blank or whitespace-only rows, provided the batch contains at least one nonblank row. Prefixing those selected edge blanks follows the explicit selected extent; it does not expand the selection. An entirely blank nonempty batch is refused for all four commands. Blank classification uses the existing Foundation whitespace/newline scalar check from list insertion.

Selections must begin at a complete physical-row boundary, including immediately after an absolute initial BOM, and end at EOF or immediately before/after a complete LF, CRLF or CR ending. Partial rows, invalid UTF-16, surrogate interiors and CRLF interiors are refused. The selected ending belongs to the preceding row: no phantom row or additional marker is created after a trailing selected ending. Existing markers, indentation, fenced-code-looking input, HTML/script-shaped source and surrounding Markdown remain literal input. These commands do not toggle/remove prefixes, infer escaping/nesting, parse context, isolate surrounding Markdown, continue typing on Return or implement rendered heading/quote UI.

At a caret, insertion is allowed only at physical row start or immediately after the initial BOM. An existing nonblank row receives only its marker; the caret ends directly after that marker and before the untouched row body. An empty or whitespace-only row receives a selected `heading` placeholder for all three heading levels or selected `text` for Blockquote. Existing whitespace and endings stay after that placeholder unchanged. EOF after a physical ending is an empty caret row. A caret before the initial BOM is refused; the BOM always remains the first source bytes.

Plans capture exact original source bytes and the exact replacement range. The resulting transformed content is selected, excluding an absolute initial BOM when selected. Original row bodies, NFD, emoji, BOM position, mixed LF/CRLF/CR endings and bytes outside the selected extent are preserved. The existing 1 MiB source/result and 64 KiB selection UTF-8 budgets apply, alongside the shared 256-physical-row bound including blank rows and replacement-growth checks. Existing list behavior, numbering, blank-row handling, `item` placeholders and regression cases remain unchanged through the generalized row-prefix helper.

## Native lifecycle and scope

Both native menus already enumerate `MarkdownInsertionCommand.allCases`; adding the four cases uses those menus without a new platform capability. Existing captured-plan staleness checks, weak view references, native insertion/undo grouping, final selection and coordinator reports remain the execution path. The native attachment, focus, editability, single-selection, marked-text and UIKit whole-document-scope guards are unchanged. The iOS block editor retains its existing suggested actions.

An accepted command is an ordinary unsaved source edit. No session identity/generation, save baseline/destination, recovery authority or close authorization is changed. The inherited outline navigation and selection-only save guard are unchanged. No clipboard read, file or URL resolution, asset import, external grant, network access, script execution, document-ingestion route or permission UI is added.
